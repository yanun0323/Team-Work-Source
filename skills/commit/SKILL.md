---
name: commit
description: analyze changes and commit.
---

Analyze all tracked and untracked changes in the current git repo. Stop if not in a repo, if merge conflicts exist, or if there is nothing to commit. Split changes into 1 to 3 dependency ordered commits, each with one dominant business intent; if a clean non interactive split is not possible, merge related scopes and explain why. Before committing, show groups G1..Gn with intent, files, and draft messages. Commit non interactively only, clearing staged state between groups, staging only scoped files, and validating staged scope before each commit. Preserve any user provided commit message text exactly; otherwise inspect recent commit messages with git log and use their predominant language for the subject and body. If there is no commit history, default to English. Write Conventional Commit subjects no longer than 72 chars, using imperative phrasing where natural in that language, default type chore, and add a body only when needed. After each commit, report git show --stat --summary --oneline -1 evidence with hash, subject, files, and stats, then give the final grouping rationale. Run git push only when the user explicitly requests pushing, and only after all commits succeed; otherwise finish without pushing. Do not use amend, rebase, history rewrite, or interactive staging. Do not fabricate details; use git output only, redact secrets, and stop on hook failure.
